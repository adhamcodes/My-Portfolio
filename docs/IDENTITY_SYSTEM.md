# ADHAM // BUILD STATE — Identity System

This portfolio is not a static resume site. It is a living representation of Adham's engineering journey.

## Core idea

The website evolves from structured state rather than redesigns.

A small set of data defines:

- current engineering stage
- active build
- shipped systems
- future direction
- project evidence
- visual state labels

The interface reads that data and reconfigures the journey automatically.

## Creative direction

**Controlled system with something alive underneath it.**

Visual language:

- graphite / near-black base
- warm near-white typography
- restrained semantic signal colors
- editorial whitespace
- precise grid
- subtle computational motion
- occasional monospace instrumentation
- no glassmorphism wallpaper
- no terminal cosplay
- no fake loading screen
- no decorative particle soup

## The opening ten seconds

1. Quiet dark canvas.
2. `ADHAM MAHMOOD` appears with minimal instrumentation.
3. A living build path constructs itself from `SOFTWARE` toward `AI SYSTEMS`.
4. Real projects branch from the path.
5. `FOUNDRY180` is visibly alive as the current build.
6. The visitor immediately understands both identity and direction.

## Signature interaction — Inspect Mode

The normal experience must remain clear to anyone.

A subtle `INSPECT` control exposes a second layer for developers:

- component boundaries
- active state
- project metadata
- system relationships
- implementation notes

This is not a fake terminal or command palette. It is the portfolio exposing its own structure.

## Content model

The primary sequence is:

1. IDENTITY
2. BUILD STATE
3. EVIDENCE
4. CURRENT EXPERIMENT
5. TRAJECTORY
6. TRANSMISSION

There are no traditional filler sections such as skill walls, service pricing, FAQ, conversion copy, or meaningless statistics.

## Project philosophy

Projects are not cards with technology badges.

Each major project should answer:

- What problem exists?
- What constraint mattered?
- What decision was made?
- How does the system work?
- What failed or changed?
- What evidence exists?

Major projects can open into an in-place technical inspection experience.

## Truthfulness

Never claim:

- a job title not earned
- production scale not demonstrated
- accessibility/performance guarantees not measured
- client work that did not occur
- skills based only on generated code

The portfolio should make ambition visible without pretending the destination has already been reached.

## Evolution rule

A future portfolio update should usually require changing files in `data/`, not rebuilding components.

Example:

```ts
foundry180.status = "shipped";
backend.status = "active";
machineLearning.status = "active";
```

The visual journey should then update naturally.

## Design law

Every unusual visual or interaction must pass both tests:

1. Does this represent Adham?
2. Does this communicate something real?

If not, remove it.
